## 1. 选题理由

**选题：排序算法可视化（终端字符画）。**（选题经 team-lead 与用户确认，见 PROJECT_STATE §6：应用选题已定 = 排序算法可视化。）

选择理由，逐条对应 LFZ 的语言能力：

1. **天然体现 LFZ 的「值皆可流」**：排序把「数组」当作数据流穿过比较/交换/归并，正好用管道 `|>`（data-last）表达 `xs |> map(...) |> join(...)`。
2. **天然体现「结构体两种面孔」**：用 `struct Stats` 同时当**计数器对象**（方法 `self.cmp += 1`）与**记录**（打印 `self.line()`），展示 struct 的对象面孔。
3. **引用语义与算法契合**：LFZ 的 `array` 是引用类型、传参按引用（SKILL §4-10 / semantics §4.5.2），原地交换 `xs[j] = v` 是合法且自然的——这让冒泡/选择/插入/快排能以教科书形式落地。
4. **可复现演示**：`seed(n)` 固定随机序列（SKILL §6），保证答辩现场每次运行得到**逐字节相同**的数组与统计，演示可控。
5. **3 分钟可讲完**：小 N 逐帧展示「算法长什么样」，大 N 一张统计表对比「算法有多快」，信息密度高、节奏清晰。

**为什么不写别的**：命令行记账/任务清单类应用依赖文件持久化，但 LFZ v1 **无文件读写内置**；猜数字/单词测验依赖 `input()`，但**非交互环境会 EOF**（实测见 §5-P3）。排序可视化是少数**不依赖外部 IO、仅靠数组+循环+管道就能闭环**且能出彩的选题。

## 5. 踩坑与修复（含语言能力限制）

> 下列 P1–P5 均有**最小复现 + 实测输出**（探针文件跑完即删，输出为本次会话转录）。

### P1（语言能力限制｜高）无模块系统 → 应用只能单文件

- **现象**：多文件「入口 + 模块」方案无法成立。
- **最小复现**（`app/_probe_import.lfz`）：
  ```lfz
  #42
  import "helpers"
  print("ok")
  ```
- **实测输出**：
  ```
  File "app/_probe_import.lfz", line 2
      import "helpers"
      ^
  SyntaxError: 这里期待 表达式，但得到 'import'
  ```
  退出码 2。依据：`syntax.md` §2.6 将 `import`/`from` 列为**未来保留字**。
- **绕行**：改单文件 + 分节；用 §4/§5/§6 注释分节，逻辑分模块（`§4 排序算法` 等）。
- **对应用的影响**：`app/` 只有一个 `.lfz` 源文件；README §4 明确说明。

### P2（语言能力限制｜高）无 CLI 参数/环境变量/文件读取 → 参数只能写进源码

- **现象**：无法用 `--n 8 --seed 42` 之类配置。
- **依据**：`cli.rs` 的 `parse_args` 只接受 `run <file>`（多参数即报错）；SKILL §0/§6 无 env/文件内置。
- **绕行**：顶部 CONFIG 常量；README §5 给「改常量→运行」的**可复现步骤**（改 `SHOW_FRAMES`、`SEED`、`N_BIG`）。
- **对应用的影响**：演示两种模式需改一行常量后重跑（任务书明确允许「改源码常量」方式）。

### P3（行为陷阱｜高）`input()` 在无 stdin 环境 EOF → IOError

- **最小复现**（`app/_probe_input.lfz`）：
  ```lfz
  #42
  print("before input")
  let x = input("? ")
  print("got " + x)
  ```
- **实测输出**：
  ```
  before input
  ? Traceback (most recent call last):
    File "app/_probe_input.lfz", line 3, in <module>
      let x = input("? ")
              ^
  IOError: 输入结束（EOF）
  ```
  退出码 2。
- **绕行**：**默认路径完全不调用 `input()`**，保证 `cargo run` 无 stdin 也退出码 0（满足 R4）。

### P4（语法陷阱｜中）`;` 是非法语句分隔符

- **最小复现**（`app/_probe_semi.lfz`）：`let x = 1; let y = 2`。
- **实测输出**：
  ```
  File "app/_probe_semi.lfz", line 2
      let x = 1; let y = 2
               ^
  SyntaxError: 语句之间必须有换行
  ```
  退出码 2。**绕行**：一语句一行（SKILL §4-1）。

### P5（语义陷阱｜中）`let` 不可重绑定、`/` 返回 float

- **最小复现**：`app/_probe_let.lfz`（`let a = 1` 后 `a = 2`）→ `TypeError: 不能重新赋值 let 变量 'a'；let 只锁重绑定，不锁内容`（退出码 2）；`app/_probe_div.lfz`（`7 / 2` 与 `div(7,2)`）→ 输出 `7 / 2 = 3.5`、`div(7, 2) = 3`（退出码 0）。
- **绕行**：累加器一律 `var`；整除一律 `div`。

### P6（实现特性｜低）容器内置返回新值 → 归并建结果有 O(n) 拷贝开销

- **现象**：`push(v, out)` 每次返回新数组（SKILL §4-10），归并排序用 `push` 逐个建结果，单次归并 O(k²)。
- **影响**：`N_BIG` 取 600（`quick`/`merge` 计数均为千级、运行瞬时）；文档提醒调大 `N_BIG` 需注意耗时。属如实记录的语言/实现特征，非缺陷。

> **未修改解释器/规范/测试**：以上均为**应用侧绕行**；`src/`、`docs/spec/`、`tests/` 一行未动。
