## 1. 语言身份（不变）

LFZ（读作 "elf-zee"）是**动态类型、表达式导向的通用脚本语言**，魂为一句话：

> **「万物皆值，值皆可流；一种结构，两种面孔。」**

- **万物皆值**：`if`、块、函数、数组、结构体全是值；块的值 = 最后一条表达式的值；函数体末尾表达式的值 = 返回值（`return` 仅用于提前退出）。
- **值皆可流**：任何值都能顺 `|>` 管道流向下一函数，`_` 占位符可把它精确塞进任意参数位。
- **一种结构，两种面孔**：复合类型仅 `array`（有序）与 `struct`（无序键值）；`struct` 同时具备对象面孔（`.字段`/方法）与字典面孔（`["键"]`），同源存储。
- **无魔法 / 确定性**：无 truthiness（条件必须 `bool`）、无隐式转换（唯一例外 `int→float` 无损加宽）、越界/缺字段/整数溢出/类型不符一律结构化报错。

**与现有语言的差异一句话**：F# 的管道（尾参注入）+ Elixir 的 `_` 插位 + Python 的动态易用与换行风格 + C 的花括号块 + Rust 的"无隐式/溢出即错"纪律 + 一种自成一体的"字典=对象"统一 struct。

## 2. 词法基础（v0.2 定稿）

### 2.1 源文本与编码

- 文件后缀 `.lfz`；UTF-8（**无 BOM**）；行尾 `LF` / `CRLF` / `CR` 均接受，统一归一化为 `\n`。
- **缩进与空白纯视觉**：`空格` / `Tab` 只作 token 分隔，**不决定块结构**（块由 `{}` 决定）。

### 2.2 多字符记号的最大匹配表（对账 #7、#9）

词法采用**最长匹配（maximal munch）**。完整记号表（长→短，**必须整体识别**）：

```
;;   =>   ==   !=   <=   >=   &&   ||   |>
+=   -=   *=   /=   %=
//   /*   */
(   )   [   ]   {   }   ,   :   .   _
=   <   >   !   +   -   *   /   %   ;
```

**禁止合成**（不存在这些记号，必须拆开）：`>>` `<<` `++` `--` `->` `..` `??` `::` `|` `&`。
即：`>` 后接 `>` 一律是两个 `>`（v1 无泛型、无移位，无风险，对账 #9）；`//` **恒为行注释**，绝不构成整除运算符（整除用内置 `div(a,b)`，见 §5-A18）。

### 2.3 注释（对账 #5-补充）

- 行注释 `// … 到行尾`（**不含**行尾换行；其后换行仍是 `NEWLINE` 记号）。
- 块注释 `/* … */`，**不可嵌套**；一个块注释经词法后**等价于一个空格**。
  - **规范性**：块注释**不产生** `NEWLINE`，**不充当语句分隔符**。跨行块注释把两行粘成一条逻辑行 → 若导致两条语句相邻则报 `E-SYN-005`（§5-A22）。

### 2.4 空白与换行

- 空白=空格/Tab/`\r`（行尾处）/块注释。
- **`NEWLINE` 是独立记号**（值 `\n`）。其"是否有效"由**解析器的换行模式栈**决定（§3.2），**不是**词法阶段按括号深度统一抑制。

### 2.5 标识符与关键字

```
IDENT = (letter | "_") , { letter | digit | "_" } ;
letter = "a"…"z" | "A"…"Z" ;
```
- **仅 ASCII**（v1 采用推荐 A；中文标识符延后）。
- **保留 token**：单独一个 `_`（下划线）**不是标识符**，而是**占位符 token** `PLACEHOLDER`（只用于管道右侧，§5-A24）。`_x`、`x_` 是普通标识符。
- **关键字（v1 保留，不可作标识符）**：
  `let` `var` `fn` `return` `if` `else` `while` `for` `in` `break` `continue` `struct` `true` `false` `nil` `self`
- **未来保留（当前使用即报 `E-SYN-001`）**：
  `match` `class` `import` `from` `try` `catch` `rescue` `yield` `async` `await` `and` `or` `not` `is`

### 2.6 数值字面量

```
INT   = dec_int | "0x" hex_digits | "0b" bin_digits | "0o" oct_digits ;
FLOAT = digit {digit|"_"} "." digit {digit|"_"} [exponent]
      | digit {digit|"_"} exponent ;            (* 指数式无小数点，如 1e10 *)
```
- `1_000`、`0xFF`、`0b1010`、`0o755`、`3.14`、`2.5e-3`、`1e10` 合法。
- **边界（消歧）**：小数点后**必须**有数字 → `1.` 是 `INT(1)` 紧跟 `.`（字段访问，§5-A23）；`.5` 非法（须写 `0.5`，`E-LEX-001`）。不存在 `..` 记号。

### 2.7 字符串与插值（结构化记号 + lexer 模式栈，对账 #8）

**词法产出结构化记号**（不是单个 `STRING` token），供 parser 组合：

```
STRING_BEGIN   TEXT(片段)   INTERP_BEGIN   <普通代码记号流>   INTERP_END   STRING_END
```

**lexer 模式栈** `M ∈ { CODE, STR, INTERP }`：

1. `CODE` 下遇 `"` → 发 `STRING_BEGIN`，push `STR`。
2. `STR` 下：
   - 普通字符 → 累积为 `TEXT`（遇 `"` 结束发 `STRING_END`）；转义 `\n \t \r \\ \" \e \$` 在 `TEXT` 中解码（`\e` = ESC 0x1B）。
   - 遇 **`${`** → 发 `INTERP_BEGIN`，置**花括号深度 `depth = 1`**，push `INTERP`，转入 `CODE`。
   - 遇未转义 `"` → 发 `STRING_END`，pop。
   - 遇 EOF → `E-LEX-002`（字符串未闭合）。
   - **`{` / `}` 在 `STR` 模式下是普通字面字符**（无特殊含义，见 §5-A14）。
3. `INTERP` 模式（即 `CODE` 模式下）：
   - `{` → `depth += 1`；`}` → `depth -= 1`；当 `depth` 归 0 → 发 `INTERP_END`，pop 回 `STR`。
   - 遇 `"` → 递归进入 `STR`（**嵌套字符串**，其内部可再 `STRING_BEGIN/INTERP_BEGIN`）；从 `STR` 返回后仍处于 `INTERP`，`depth` 不变。
   - 在 `depth == 1`（相对 `INTERP` 的顶层）且遇到第一个 `:` → 记为 **format-spec 分隔点**，`: ` 之后到匹配 `}` 之间是 `format_spec` 文本（其中不含花括号）。`depth > 1` 的 `:`（如 `{a:1}`）**不切分**。
   - 遇到 `INTERP` 的 EOF → `E-LEX-002`。
4. 后缀格式说明符（沿用 v1）：
   ```
   format_spec = [ [fill] align ] [sign] [width] [ "." precision ] [type] ;
   align = "<" | ">" | "^" ;  type = "d" | "x" | "X" | "o" | "b" | "f" | "e" | "s" ;
   ```
   非法说明符 `E-FMT-001`；说明符与值类型不符 `E-FMT-002`。

**无冲突理由（规范性）**：块/字面量的 `{}` 出现在 `CODE` 模式；插值仅由 `$` 前缀的 `${` 触发且发生在 `STR`→`INTERP` 模式内。两个字符集在**模式上互斥**，故 `${…}` 与块花括号**不可能冲突**。`$` 后非 `{` → 字面 `$`（`"$5"` = `$5`）。

## 3. 语句、块、换行（用户指令 2/3/4 的落地）

### 3.1 语句终结规则（否定式，值得先记）

- **没有**语句分隔符。**一条语句占一条逻辑行**（same-line 两条语句**不可能**）。
- **唯一**的换行续行手段是**括号**：`( … )`、`[ … ]`，以及**字面量/声明体** `{ … }`。括号内换行被忽略。
- **不允许**行尾运算符续行，**不允许**反斜杠续行（v1），**不允许**行首 `.`/`|>` 续行（§5-A2，与 core-dev #5 部分分歧，见 §9）。

### 3.2 解析器换行模式栈（对账 #4，**必须由 parser 管理**）

> 为什么不能只按 lexer 括号深度？因为块可嵌在 `()`/`[]` 里，例如 `f(fn(x){ let y=x \n y })`——若在 `(` 内统一抑制换行，块内语句就会粘连。故换行是否有效**只能由 parser 依上下文决定**。

解析器维护 `NLMode ∈ { SIG, IGN }` 栈（初始 = `SIG`）：

| 进入构造 | push | 该上下文内`NEWLINE` |
|---|---|---|
| 程序顶层 / **块 `{`**（if/while/for/fn/lambda/else 的函数体） | `SIG` | **有效**：终结语句 |
| 实参表 `( … )`、数组字面量 `[ … ]`、**struct 字面量/声明的成员表 `{ … }`** | `IGN` | **忽略**：当空白跳过 |

- `IGN` 模式下：解析器**跳过**所有 `NEWLINE` 记号。
- `SIG` 模式下：`NEWLINE` 终结当前语句。
- 嵌套时**各构造独立 push/pop**：例如 `f(fn (x) { … })` 中，`(` 压 `IGN`，块 `{` 再压 `SIG`，块内换行有效；块闭合 pop 回 `IGN`。
- **块 `{` 与 字面量 `{` 的判定**：完全由**文法位置**决定（§3.3），不靠词法。

**语句终结检查**：每条语句解析完后，下一个有效记号**必须**是 `NEWLINE`（消费连续多个）、`}` 或 `EOF`；否则 `E-SYN-005`（同一逻辑行出现两条语句）。

### 3.3 `{` 的两种角色：块 vs struct 字面量（对账 #4、#2）

按**文法位置**二分，二者并集覆盖全部可能，无重叠：

1. **块位置（block-required）**：紧跟下列头部之后（中间允许换行，见 §3.5）：
   `if <expr>`、`else`、`while <expr>`、`for <id> in <expr>`、`fn <name>(<params>)`、`fn (<params>)`、`(<params>) =>`、`struct <Name>`。
   → 此处 `{` **是块**。
2. **表达式位置**：其余一切期待表达式之处遇到 `{`（可选前置类型名 `IDENT`）→ **struct 字面量**。
   - 含**语句起始处**的 `{`：LFZ **没有"裸块语句"**，故语句首 `{` 恒为**匿名 struct 字面量**（§5-A9）。
   - **例外**：`if`/`while` 条件位与 `for` 可迭代位**禁止裸 struct 字面量**（Rust 规则，§3.4 / §5-A6）。

### 3.4 控制流条件位的"禁裸花括号"规则（对账 #2，**采纳 Rust 规则**）

> 问题：`IDENT {` 是"模板实例化"（`Student { x:1 }`），故 `if c { }` 会被误读为条件 `c{…}`。

**规则（规范性）**：解析 `if`/`while` 的条件表达式、`for … in` 的可迭代表达式时，进入 **NO_BRACE_LITERAL 模式**：

- 在该表达式的**最外层**（不在任何 `()`/`[]` 内）遇到 `{` → **终止表达式**，该 `{` 交给块。
- 进入 `(`/`[` 时**临时清除**该限制；离开时**恢复**（只在"最外层"生效）。
- 因此条件里要用 struct 字面量，**必须加括号**。

```
// 正例：字面量被括号包住，`{` 属于块
if ({ x: 1 }.x) > 0 { print("ok") }

// 反例：`{` 被当作块，条件只剩 `Point`，块体 `x: 1` 非法 → E-SYN-001
if Point { x: 1 }.x > 0 { print("no") }
```

### 3.5 头部与块之间的换行（对账 #5、#6）

- **块前换行**：当文法**期待一个块**时，解析器先**跳过**任意 `NEWLINE`，再期待 `{`。故
  ```
  if x > 0
  {
      print("ok")
  }
  ```
  合法。块的首行 `NEWLINE` 在 `SIG` 模式下是块内的空行，无害。
- **`else` 前换行**：解析完 `if` 的 consequence 块后，解析器**保存位置 → 跳过 `NEWLINE` 们 → 看下一个有效记号是否为 `else`**；是则消费并解析 `else` 分支，否则**回退**（这些换行仍作语句分隔）。
  ```
  if a { 1 }
  else if b { 2 }
  else { 3 }        // 合法
  ```
- 花括号使块边界明确，故悬挂 `else` **不存在**：`else` 一律绑定**最近的、尚未闭合的** `if`（§5-A4）。

### 3.6 `;;` —— 变量 dump 语句（用户指令 4）

**语法**：`;;`（**两个相邻 `;` 字符，中间不可有空白/注释**）= 一个 `DUMP` 记号 = 一条**独立语句**，**独占其逻辑行**。

**语义（规范性）**：

1. **触发点**：执行到 `;;` 时，立即输出当前可见变量。
2. **作用域 = 当前可见名字链**：从**最内层作用域向外**遍历（与名字解析完全一致，含块作用域、函数局部、闭包捕获、模块顶层）。
3. **顺序**：
   - 作用域顺序：**内层 → 外层**。
   - 同一作用域内：按 **slot 下标升序**（= 声明/首次绑定顺序）。
   - **遮蔽去重**：同名变量只打印**最内层（即可见）的那个绑定**；每个名字**恰好一行**。
4. **内容**：**所有绑定**，含 `let`/`var`、函数参数、`fn` 名、`struct` 模板名。
5. **行格式（逐字符精确定义）**：
   ```
   <name> + " ： " + <value>
   ```
   其中分隔串 = `U+0020`(空格) `U+FF1A`(全角冒号 `：`) `U+0020`(空格)。
6. **值渲染** = 与 `print`/`str()` **同一显示形式**（§3.7）。
7. **通道**：**stdout**（与 `print` 同通道，按程序执行顺序交织）。
8. **空链**：无可见变量时输出**零行**，不报错。
9. **可重入**：函数内 `;;` 打印**该次调用**的局部链；不同调用各自输出。

```
let a = 1
fn f(n) {
    let b = 2
    ;;                 // 输出（内→外）：
}                      //   b ： 2
f(10)                  //   n ： 10
                       //   a ： 1
                       //   （f 的函数名绑定也在链上，视其声明位置）
```

### 3.7 值的显示形式（供 `print` / `;;` / `str()` 复用）

| 类型 | 顶层 | 嵌套在 array/struct 内 |
|---|---|---|
| `nil` | `nil` | `nil` |
| `bool` | `true`/`false` | 同 |
| `int` | 十进制 | 同 |
| `float` | 最短往返；整值浮点显示 `.0`（`1.0`） | 同 |
| `string` | **原样，不加引号** | **加 `"`，内部按转义输出** |
| `array` | `[e1, e2, …]`（逗号+空格） | 同 |
| `struct` 实例 | `{k1: v1, k2: v2}`，**键按字节序升序** | 同 |
| `function` | `<fn 名字>`（匿名 `<fn>`） | 同 |
| `struct` 模板 | `<struct 名字>` | 同 |

## 4. 表达式、运算符与优先级

### 4.1 优先级表（高 → 低，全部左结合）

| 级别 | 运算符 | 说明 | 结合性 |
|---|---|---|---|
| 1（最紧） | `()` `[]` `.` | 调用 / 索引 / 字段（postfix） | 左 |
| 2 | `-` `!`（一元前缀） | 取负 / 逻辑非 | 右（前缀） |
| 3 | `*` `/` `%` | 乘 / 除 / 取模 | 左 |
| 4 | `+` `-` | 加 / 减 / 字符串连接 | 左 |
| 5 | **`\|>`** | **管道** | 左 |
| 6 | `<` `<=` `>` `>=` | 比较 | 左 |
| 7 | `==` `!=` | 相等 | 左 |
| 8 | `&&` | 短路与 | 左 |
| 9（最松） | `\|\|` | 短路或 | 左 |

直观规则：**`|>` 比 `+ - * / %` 松，比任何比较/逻辑都紧**（Elixir 位置）。

### 4.2 类型化运算符（无隐式转换，特色 5）

- `+`：`int+int`、`float+float`、`string+string`（连接）。
- `- * / %`：数值。
- `*`：额外支持 `string * int`（重复，`"█" * 5`）。
- 比较：数值之间、`string` 之间（UTF-8 字节序）；`bool` 仅 `== !=`；`nil` 仅 `== !=`。
- `==`/`!=`：标量按值；`array`/`struct` **深结构相等**；`function` **同一性**。
- `&& ||`：两侧与结果都必须 `bool`，短路求值。
- **`int`/`float` 混合**：唯一隐式转换——`int` 在算术/比较中**无损加宽**为 `float`（v1 Q4 推荐 B，D-011）。

### 4.3 管道语义（特色 1，parser 阶段脱糖，运行时零开销）

**语法**：`pipe_expr = add_expr { "|>" pipe_rhs }`，`pipe_rhs = postfix | lambda`（即右侧必须是"可调用形状"：函数名 / 调用 / 方法访问 / lambda）。

**脱糖规则**（解析期）：

1. `L |> F(a1,…,an)`：若参数中**恰有一个 `_`** → 把 `L` 替换该位；**无 `_`** → `L` **追加为末参**（data-last）；**≥2 个 `_`** → `E-PIPE-002`。
2. `L |> R`（R 非调用：函数名/方法/lambda）→ `R(L)`。
3. `R` 求值后不是函数 → 运行时 `E-PIPE-001`。
4. `_` 出现在右侧之外 → `E-PIPE-003`（含 `let _ = …` 绑定）。
5. `L |> R1 |> R2` 左结合 = `R2(R1(L))`；`_` 可出现在右侧调用实参的**任意嵌套深度**。

```
let total = [1,2,3,4,5] |> filter((x) => x % 2 == 1) |> map((x) => x * x) |> sum()   // 55
print(10 |> div(_, 2))     // 5     （任意位插入）
print(2  |> div(10, _))    // 5
```

### 4.4 管道优先级的修正（对账 #1，**真 bug 已修**）

v1 草案**表**称 `|>` 比 `* /` 松，但 **EBNF** 写成 `mul = pipe {(*|/) pipe}`（等于 `*` 比 `|>` 松）——**自相矛盾**。v0.2 **以表为准**，修正文法层序为：

```
cmp_expr  = pipe_expr { ("<"|"<="|">"|">=") pipe_expr } ;
pipe_expr = add_expr  { "|>" pipe_rhs } ;
add_expr  = mul_expr  { ("+"|"-") mul_expr } ;
mul_expr  = unary     { ("*"|"/"|"%") unary } ;
unary     = ("-"|"!") unary | postfix | if_expr | lambda ;
```
验证（唯一解）：
- `1 + 2 |> f` → `(1+2) |> f` → `f(3)` ✅
- `xs |> sum() > 10` → `(xs |> sum()) > 10` ✅
- `xs |> sum() + 1` → **语法错误**（`|>` 右侧仅收 `pipe_rhs`，`+1` 无处安放）→ 须写 `(xs |> sum()) + 1`。**这是有意为之、且已写死**（§5-A2）。

## 5. 歧义审计与消解（本次核心交付）

> 每条格式：**潜在歧义** → **消解规则** → **正例** / **反例**（括号内为错误码）。

### A1. 换行终结语句 vs 括号内换行
- **歧义**：一行内多语句？括号内换行是否断句？
- **规则**：NL 模式栈（§3.2）。`SIG` 内 `NEWLINE` 终结语句；`IGN`（`()`/`[]`/字面量`{}`）内 `NEWLINE` 当空白。语义**只能**由 parser 上下文判定。
- 正例：`f(a,\n  b)` 合法；反例：`let x = 1 let y = 2` → `E-SYN-005`。

### A2. 行尾运算符是否续行
- **歧义**：`1 +\n2` 是一句还是两句？
- **规则**：**不续行**（Python 式）。行尾运算符在 `SIG` 下语句就此结束，表达式不完整 → `E-SYN-002`。
- 正例：`let x = (1 +\n 2)`（括号续行）；反例：`let x = 1 +\n2` → `E-SYN-002`。

### A3. `{` 前换行
- **歧义**：`if c` 换行后 `{` 是块吗？
- **规则**：**块期待位**（§3.3）先跳过换行再见 `{`，合法；**表达式位**的换行照常终结语句。
- 正例：`if c\n{ … }`；反例：`let p = Foo\n{ x: 1 }` → 两句（`let p = Foo` + 匿名字面量语句），**非**一个带标签的字面量（陷阱，须写一行或加括号）。

### A4. `else` 与 `if` 的换行 / 悬挂 else
- **歧义**：`else` 归属？`else` 能否另起一行？
- **规则**：解析完 if 体后**跳过换行看 `else`**；有则绑定最近的未闭合 `if`。花括号使绑定唯一（无 dangling-else）。
- 正例：`if a {1}\nelse {2}`；反例：`if a {1}\nelse {2}\nelse {3}` → 第二个 `else` 无主 → `E-SYN-001`。

### A5. `{}` 双重角色（块 vs 字面量）
- **歧义**：`{` 是块还是结构体？
- **规则**：**文法位置**判定（§3.3）。块仅在 block-required 位；其余为字面量；**无裸块**。
- 正例：`while c { … }`（块） / `let d = { "k": 1 }`（字面量）；反例：无（位置互斥覆盖）。

### A6. `if c { … }` 被吞块（标签字面量）
- **歧义**：`if IDENT { … }` 中 `{ … }` 是块还是 `IDENT{…}` 字面量？
- **规则**：条件/可迭代位 **NO_BRACE_LITERAL**（Rust 规则，§3.4），`{` 必为块；要放字面量须加括号。
- 正例：`if ({x:1}.x) > 0 { }`；反例：`if Point { x:1 }.x > 0 { }` → `E-SYN-001`。

### A7. struct 字段/成员分隔符（对账 #10）
- **歧义**：字段用逗号还是换行？
- **规则**：**逗号必填**，尾逗号可选；**字面体与声明体一致**；其 `{}` 内换行**忽略**（§3.2）。
- 正例：`Student { name: "A", score: 1 }`、多行时每行结尾逗号；反例：`Student {\n name: "A"\n score: 1\n}`（缺逗号）→ `E-SYN-001`。

### A8. 数组元素 / 实参跨行
- **歧义**：换行可否代替逗号？
- **规则**：**逗号必填**，换行忽略，尾逗号可选（同 A7）。
- 正例：`[1,\n 2,\n 3,]`；反例：`[1\n 2]` → `E-SYN-001`。

### A9. 语句首 `{`
- **歧义**：裸块 vs 匿名字面量？
- **规则**：**恒为匿名 struct 字面量**（表达式语句）；LFZ 无裸块语句。
- 正例：`fn config() {\n { host: "x" }\n}`（末尾返回匿名结构体）；反例：`{ let x = 1 }` → `E-SYN-001`（`let` 不是字面量字段）。

### A10. `;;` 触发与位置
- **歧义**：`;;` 独占一行还是可挂行尾？是否允许空白分隔？
- **规则**：`;;` 为**两个相邻 `;`** 组成的单一记号；是**独立语句**，**独占逻辑行**；允许行首/行尾空白与尾随 `//` 注释；**不得**与其他内容同行。
- 正例：`;;` / `   ;;   // 看变量`；反例：`x = 1 ;;` → `E-SYN-005`（同行两语句）。

### A11. 单个 `;`
- **歧义**：`;` 是空语句/分隔符吗？
- **规则**：`;` 词法合法（`SEMI`）但**文法从不接受** → 语法错误 `E-SYN-003`（提示改用 `;;`）。**取消** v1 的"空语句"概念。
- 反例：`x = 1;` → `E-SYN-003`。

### A12. `;;;` / `; ;`
- **歧义**：更多分号的切分？
- **规则**：**最长匹配**：`;;`=DUMP，`;`=SEMI。故 `;;;` = `DUMP` `SEMI` → `E-SYN-003`；`; ;` = `SEMI SEMI` → `E-SYN-003`；`;;;;` = `DUMP DUMP`（同行两语句）→ `E-SYN-005`。
- 反例：`;;;`、`; ;`、`;;;;` 全部报错（错误码如上）。

### A13. `;;` 输出通道/顺序/作用域
- **歧义**：打到 stdout 还是 stderr？哪些变量、什么顺序？
- **规则**：§3.6——**stdout**、**内层→外层**、同层按 **slot 升序**、**遮蔽去重**、行格式 `<name> ： <value>`（`：`=U+FF1A）。
- 正例：见 §3.6 `f(10)` 例；反例：无（顺序/通道已写死）。

### A14. 插值 `${}` 与块花括号是否冲突
- **歧义**：字符串里的 `{` 是插值还是普通字符？
- **规则**：字符串内 `{`/`}` **是普通字面字符**；插值**必须**由 `${` 触发（模式栈，§2.7）。故与代码块 `{}` **不可能冲突**（字符集在 lexer 模式上互斥）。
- 正例：`"a { b } c"` → 字面 `a { b } c`；`"a ${x} c"` → 插值；反例：`"a {x} c"` 期望插值 → 实际是字面文本（**这不是歧义，是定义**；要插值请写 `${x}`）。

### A15. 插值转义 / 嵌套 / `:` 切分
- **歧义**：如何输出字面 `${x}`？内层 `:` 会不会被当格式分隔？
- **规则**：`\${` 输出字面 `${`；`$` 后非 `{` 即字面 `$`。嵌套按花括号深度配对并跳过内层字符串；**只切分 `depth==1` 处第一个 `:`**。
- 正例：`"\${x}"` → `${x}`；`"${ {a: 1}.a }"` → `1`（`:` 在深度 2，不切分）；反例：`"${x"` → `E-LEX-002`。

### A16. 一元负号 vs 减法
- **歧义**：`a - b` / `a -b` / `a--b`？
- **规则**：`-` 恒为单一记号；**前缀位**=一元，**中缀位**=减法。无 `--`/`++` 记号，故 `a--b` = `a - (-b)`。
- 正例：`a - -b`、`a--b`、`-(-1)`（=1）；反例：无（唯一解）。

### A17. 管道 `|>` 与换行
- **歧义**：管道链能否跨行？
- **规则**：只能在**同一逻辑行**，或**括号内跨行**（`|>` 不续行、不作行首续行，§5-A2）。
- 正例：`(xs\n |> f()\n |> g())`；反例：`xs\n |> f()` → 第二行以 `|>` 开头 → `E-SYN-001`。

### A18. `|>` vs `||` vs `|`；`=>` vs `==` vs `=`；`//` vs 除
- **歧义**：`|` 系与 `=` 系的最长匹配。
- **规则**：最大匹配表（§2.2）。**单独 `|` / 单独 `&` 非法**（`E-LEX-001`）；`||` 与 `|>` 互斥；`==` 先于 `=`、`=>` 先于 `=`。`//` **恒为注释**。
- 正例：`a |> b`、`a || b`、`x => x`、`a == b`、`a = b`；反例：`a | > b`、`a ||> b`（`||` 后 `>` 意外）、`6//2`（`//` 起注释，无整除）→ 报错或非预期（须 `div(6,2)`）。

### A19. `return`/`break`/`continue` 后换行
- **歧义**：`return` 后换行的表达式是否属它？
- **规则**：**`return` 行尾 = 返回空（`nil`）**；返回值**必须**与 `return` 同行。`break`/`continue` 无表达式，天然无歧义。
- 正例：`return x + 1` / 单行 `return`（返 nil）；反例：`return\n x + 1` → 返回 nil，随后 `x+1` 成独立表达式语句（**陷阱**，不报错，须注意）。

### A20. lambda `(params) => …` vs 括号表达式
- **歧义**：`(x)` 是参数表还是括号表达式？
- **规则**：`( … )` 后**前瞻 `=>`** → lambda；含**逗号**的形式（`(a, b)`）**只可能是参数表**（无逗号表达式）。`(a+b) => c` → 参数非标识符 → `E-SYN-001`。
- 正例：`map((x, y) => x + y, xs)`；反例：`(a + b) => c` → `E-SYN-001`。

### A21. 赋值 vs 表达式语句（lvalue）
- **歧义**：`f() = 1` 是赋值吗？
- **规则**：先按表达式解析；若其后紧跟 `assign_op`，则该表达式**必须**是 lvalue（`IDENT` 起点 + `.`/`[]` 后缀），否则 `E-SYN-006`；否则为表达式语句。`==` 属表达式层，先于赋值检查。
- 正例：`a.b[0] = 1`；反例：`f() = 1`、`a + b = 1` → `E-SYN-006`。

### A22. 块注释跨行是否作分隔符
- **歧义**：`/* …\n… */` 里的换行算不算语句分隔？
- **规则**：**不算**（注释等价空格）。若因此粘出两条语句 → `E-SYN-005`。
- 正例：`let x = 1\n/* c */ let y = 2`（有真换行）；反例：`let x = 1 /* c\nc */ let y = 2` → `E-SYN-005`。

### A23. 数值字面量边界
- **歧义**：`1.`、`.5`、`1.e3`？
- **规则**：小数点后**必须**有数字；前导小数点不许。
- 正例：`1.0`、`0.5`、`2.5e-3`；反例：`1.`（= `1` 后 `.`，字段访问 → 运行时/语法错）、`.5` → `E-LEX-001`。

### A24. `_` 占位符 vs 标识符
- **歧义**：`_` 是变量名吗？
- **规则**：**单独 `_` = 占位符 token**，仅可作 `|>` 右侧调用实参；绑定/主位使用 → `E-PIPE-003`。`_x`/`x_` 是普通标识符。
- 正例：`xs |> f(_)`；反例：`let _ = 1`、`_ + 1` → `E-PIPE-003`。

### A25. `>>` 不合成
- **歧义**：`a >> b` 是否被误合成移位记号？
- **规则**：**禁止**——lexer 拆成 `>` `>`；v1 无泛型/无移位，无冲突。
- 正例：`a > > b` 与 `a>>b` 均拆为两个 `>`（`a>>b` 解析为比较链 → `E-SYN-001`）；反例：无。

### A26. `if`/lambda 后直接后缀调用
- **歧义**：`if c {1} else {2}(x)` 的 `(x)` 归属？
- **规则**：`if_expr`/`lambda` 位于 `unary` 层，**不作 postfix 基**；直接后缀**不适用**，要调用其结果须加括号。
- 正例：`(if c {1} else {2})(x)`；反例：`if c {1} else {2}(x)` → `E-SYN-001`。

**审计条目数：26（A1–A26）。**

## 6. EBNF（ISO EBNF，v0.2 修订版）

```
(* ============================================================
   LFZ v0.2 grammar — ISO EBNF
   记法: = 定义 ; , 连接 ; | 选择 ; { } 0..n ; [ ] 可选 ; " " 终结符
   约定:
   - NEWLINE 是否有效由「解析器换行模式栈」决定（§3.2），非词法统一处理。
   - 块仅在 block-required 位；其余 { 为 struct 字面量（§3.3）。
   - if/while 条件位、for 可迭代位禁用裸 struct 字面量（§3.4）。
   - 所有二元运算符左结合；优先级见 §4.1。
   ============================================================ *)

program        = { NEWLINE | statement } , EOF ;
block          = "{" , { NEWLINE | statement } , "}" ;
(* 规范性: 相邻两 statement 之间必须 ≥1 个 NEWLINE; statement 后可直接为 "}" 或 EOF。
   违反 -> E-SYN-005。 *)

statement      = decl_stmt | assign_stmt | fn_decl | struct_decl
               | while_stmt | for_stmt
               | return_stmt | break_stmt | continue_stmt
               | dump_stmt | expr_stmt ;

decl_stmt      = ( "let" | "var" ) , IDENT , "=" , expression ;
assign_stmt    = lvalue , assign_op , expression ;
assign_op      = "=" | "+=" | "-=" | "*=" | "/=" | "%=" ;
lvalue         = IDENT , { "." , IDENT | "[" , expression , "]" } ;

fn_decl        = "fn" , IDENT , "(" , [ params ] , ")" , body ;
body           = block | "=>" , expression ;
struct_decl    = "struct" , IDENT , "{" , [ member_list ] , "}" ;
member_list    = member , { "," , member } , [ "," ] ;
member         = fn_decl | IDENT , ":" , expression ;

while_stmt     = "while" , expression , block ;
for_stmt       = "for" , IDENT , "in" , expression , block ;
return_stmt    = "return" , [ expression ] ;          (* 换行即返回空 *)
break_stmt     = "break" ;
continue_stmt  = "continue" ;
dump_stmt      = ";;" ;                                (* 独占逻辑行 *)
expr_stmt      = expression ;

params         = IDENT , { "," , IDENT } ;

(* -------- 表达式: 高 precedence -> 低 -------- *)
expression     = or_expr ;
or_expr        = and_expr , { "||" , and_expr } ;
and_expr       = eq_expr  , { "&&" , eq_expr } ;
eq_expr        = cmp_expr , { ( "==" | "!=" ) , cmp_expr } ;
cmp_expr       = pipe_expr , { ( "<" | "<=" | ">" | ">=" ) , pipe_expr } ;
pipe_expr      = add_expr , { "|>" , pipe_rhs } ;
add_expr       = mul_expr , { ( "+" | "-" ) , mul_expr } ;
mul_expr       = unary    , { ( "*" | "/" | "%" ) , unary } ;
unary          = ( "-" | "!" ) , unary | postfix | if_expr | lambda ;
postfix        = primary , { call | index | field } ;
call           = "(" , [ args ] , ")" ;
index          = "[" , expression , "]" ;
field          = "." , IDENT ;
args           = expression , { "," , expression } , [ "," ] ;
pipe_rhs       = postfix | lambda ;

primary        = INT | FLOAT | STRING
               | "true" | "false" | "nil" | "self"
               | IDENT | "_"
               | array_lit | struct_lit
               | "(" , expression , ")" ;

array_lit      = "[" , [ args ] , "]" ;
struct_lit     = [ IDENT ] , "{" , [ field_list ] , "}" ;
field_list     = field_init , { "," , field_init } , [ "," ] ;
field_init     = ( IDENT | STRING ) , ":" , expression ;

if_expr        = "if" , expression , block ,
                 [ "else" , ( if_expr | block ) ] ;
lambda         = "fn" , "(" , [ params ] , ")" , body
               | "(" , [ params ] , ")" , "=>" , ( expression | block ) ;

(* -------- 词法 -------- *)
IDENT          = ( letter | "_" ) , { letter | digit | "_" } ;   (* 单独 "_" 除外 *)
letter         = "a" | ... | "z" | "A" | ... | "Z" ;
digit          = "0" | ... | "9" ;
INT            = dec_int | "0x" , hex_digits | "0b" , bin_digits | "0o" , oct_digits ;
dec_int        = digit , { digit | "_" } ;
FLOAT          = digit , { digit | "_" } , "." , digit , { digit | "_" } , [ exponent ]
               | digit , { digit | "_" } , exponent ;
exponent       = ( "e" | "E" ) , [ "+" | "-" ] , digit , { digit } ;
NEWLINE        = "\n" | "\r\n" | "\r" ;
COMMENT        = "//" , { any_except_newline } | "/*" , { any } , "*/" ;

(* 字符串: 结构化记号（lexer 产出, parser 组合） *)
STRING         = STRING_BEGIN , { TEXT | interpolation } , STRING_END ;
interpolation  = INTERP_BEGIN , expression , [ ":" , format_spec ] , INTERP_END ;
format_spec    = [ [ fill ] , align ] , [ sign ] , [ width ] ,
                 [ "." , precision ] , [ type ] ;
align          = "<" | ">" | "^" ;
type           = "d" | "x" | "X" | "o" | "b" | "f" | "e" | "s" ;
```

**maximal-munch 记号表**：见 §2.2。
**错误码表**：见 §7。

## 7. 错误模型（v0.2 增补）

新增/修订（其余沿用 v1 §4）：

| 码 | 类别 | 触发条件 | 消息模板 |
|---|---|---|---|
| `E-LEX-001` | lex | 非法字符（含 `\|`、`&`、`'`、`.5`） | `非法字符 '{c}'` |
| `E-LEX-002` | lex | 字符串/插值未闭合 | `字符串字面量在此处未闭合` |
| `E-SYN-001` | syntax | 意外 token | `这里期待 {expected}，但得到 {got}` |
| `E-SYN-002` | syntax | 表达式在行尾不完整（未加括号续行） | `表达式未结束：行尾不能终止表达式；请用括号跨行` |

| `E-SYN-005` | syntax | 同一逻辑行出现两条语句 / 缺终止 | `语句之间必须有换行` |
| `E-SYN-006` | syntax | 赋值目标非法 | `赋值左侧必须是变量、字段或下标` |

（`E-SYN-004` 保留未用，留给后续。）

## 8. 样例程序（v0.2 语法，含 `;;`）

### 8.1 样例 A —— 学生成绩统计（完整程序，含 `;;`）

```
// ============================================================
// grades.lfz — 学生成绩统计（v0.2 语法）
// 覆盖: struct/方法、array、函数、while/for/if、
//       字符串插值、管道 |>、assert、基本 IO、;; 变量 dump
// ============================================================

struct Student {
    name: "",
    score: 0,
    fn isTop() => self.score >= 90,
    fn line() => "${self.name}: ${self.score:>3}",
}

fn sortDesc(xs) {
    var pool = xs
    var out = []
    while len(pool) > 0 {
        var best = 0
        for i in range(len(pool)) {
            if pool[i].score > pool[best].score { best = i }
        }
        out = push(pool[best], out)
        pool = removeAt(best, pool)
    }
    out
}

fn average(xs) {
    assert(len(xs) > 0, "average() 需要非空数组")
    var total = 0.0
    for s in xs { total += float(s.score) }
    total / float(len(xs))
}

let roster = [

    Student { name: "Bob",   score: 67 },
    Student { name: "Cara",  score: 88 },
]

for s in roster { print("  " + s.line()) }

let ranked = roster |> sortDesc()

print("")
print("排名：")
var rank = 1
for s in ranked {
    let star = if s.isTop() { "★" } else { "·" }
    print("  ${rank}. ${star} ${s.line()}")
    rank += 1
}

print("")
print("平均分 = ${average(roster):.2f}")
```

### 8.3 样例 C —— 排序可视化核心片段（服务 P8 应用，片段）

```
// bars.lfz — ASCII 排序可视化核心片段（v0.2 语法）
print("\e[2J\e[H")                     // ANSI 清屏+归位（\e = ESC 0x1B）
seed(12345)                            // 固定随机种子 → 演示可复现
var xs = range(40) |> map((i) => randInt(5, 100))

fn draw(a, hi) {
    var out = "\e[H"
    for i in range(len(a)) {
        let bar = "█" * a[i]           // string * int = 重复
        out += if i == hi { "${bar}  << " } else { bar + "\n" }
    }
    print(out)
}

for i in range(len(xs)) {
    for j in range(len(xs) - i - 1) {
        if xs[j] > xs[j + 1] { xs = xs |> swap(j, j + 1) }
        draw(xs, j)
    }
}
;;
print("排序完成")
```

## 9. 对 core-dev 审计的对账

> 逐条给出：**同意 / 部分同意 / 不同意** + 理由 + **最终采纳的规则**。

**#1 管道 EBNF 与优先级表矛盾（真 bug）—— 同意（并已独立复现该 bug）。**
- 理由：`1 + 2 |> f` 在 `mul = pipe {(*|/) pipe}` 下会算成 `1 + (2|>f)`，与表冲突。
- **最终规则**：采纳 core-dev 的修正层序 `cmp = pipe {(<|<=|>|>=) pipe}; pipe = add {"|>" pipe_rhs}; add = mul {(+|-) mul}; mul = unary {(*|/|%) unary}; unary = (-|!) unary | postfix | if_expr | lambda`（§4.4）。**并写死**：`|>` 右侧只收 `pipe_rhs`（可调用形状），故 `xs |> sum() + 1` 是**语法错误**，须写 `(xs |> sum()) + 1`。

**#2 `if c { … }` 被误读 —— 同意（并已独立发现）。**
- 理由：`IDENT {` 是模板实例化，条件以标识符结尾会吞块。
- **最终规则**：采纳 **Rust 的 NO_STRUCT_LITERAL 限制**——`if`/`while` 条件位、`for … in` 可迭代位**禁止裸 struct 字面量**；进入 `()`/`[]` 时临时解除，离开恢复；需要时加括号（§3.4、A6）。

**#3 `;` / `;;` 记号化 —— 同意。**
- 理由：取消"空语句"概念后 `;;` 才不会退化成两个空语句。
- **最终规则**：**最长匹配**——相邻（无空白）`;;` = `DUMP`（专用打印记号）；单独 `;` 词法合法但**文法不接受** → `E-SYN-003`；`;;;` = `DUMP`+`SEMI` → `E-SYN-003`；`; ;` = 两个 `SEMI` → `E-SYN-003`；`;;;;` = 两个 `DUMP` → 同行两语句 `E-SYN-005`（A10–A12）。

**#4 `{}` 双角色 + 换行必须由 parser 管理 —— 同意。**
- 理由：块可嵌在 `()`/`[]` 内（`f(fn(x){ … })`），按 lexer 括号深度统一抑制会破坏块内语句。
- **最终规则**：引入**解析器换行模式栈** `NLMode ∈ {SIG, IGN}`（§3.2）；`SIG` 内 NEWLINE 终结语句，`IGN`（`()`/`[]`/字面量-`{}`成员表）内忽略；构造独立 push/pop；`{` 的角色**纯按文法位置**判定（§3.3）。

**#5 换行终结（ASI）细则 —— 部分同意。**
- **同意**：`return` 行尾 = 返回空（`nil`），返回值须同行（A19）；语句终结必须有二值可判定的规则。
- **不同意**：不采纳"行尾运算符续行 + 行首 `.`/`|>` 安全续行"的组合。理由：
  1. 行首续行是**跨行回溯拼接**，会让"上一行是否成句"取决于下一行首记号，推理面变大（弱化"无歧义"目标）；
  2. 用户指令 #1 明确"大体参考 Python"，而 Python **只**在括号内隐式续行、行尾运算符不续行；
  3. 括号化已完全解决问题，无需引入两套续行机制。
- **最终规则**：**括号是唯一续行手段**（§3.1）；行尾运算符在 `SIG` 下 → `E-SYN-002`（A2）。行首续行/尾随运算符续行记入待确认项（§11）。

**#6 悬挂 else + `else` 前换行抑制 —— 同意。**
- **最终规则**：解析完 if 体后**保存位置→跳过 `NEWLINE`→看 `else`**，是则消费、否则回退；花括号使 `else` 唯一绑定最近未闭合 `if`（§3.5、A4）。

**#7 一元负号 + 多字符记号最大匹配表 —— 同意。**
- **最终规则**：`-` 单记号，前缀=一元 / 中缀=减法；无 `--`/`++`/`->`；给出完整最长匹配表（§2.2），并**禁止**合成 `>> << ++ -- -> .. ?? ::`（A16、A25、§2.2）。

**#8 字符串插值需要 lexer 模式栈 + 结构化记号 —— 同意。**
- **最终规则**：lexer 产出 `STRING_BEGIN / TEXT / INTERP_BEGIN / … / INTERP_END / STRING_END`；模式栈 `CODE/STR/INTERP`；按花括号深度配对、跳过内层字符串、仅在 `depth==1` 处切分第一个 `:` 作 format-spec 分隔（§2.7、A14、A15）。算法已写全。

**#9 `>>`/泛型无风险，须防误合成 —— 同意。**
- **最终规则**：lexer **禁止**把 `>>` 合成为单一记号（拆成 `>` `>`）；v1 无泛型、无移位，无冲突（§2.2、A25）。

**#10 分隔符一致性（声明体 vs 字面体）—— 同意。**
- 理由：草案 v1 让声明体可用换行分隔、字面体必须逗号，是学习者陷阱。
- **最终规则**：**统一**——struct **声明体与字面体的成员一律逗号必填**、尾逗号可选、其 `{…}` 内换行忽略（§3.2、A7、A8）。理由：这两处 `{…}` 都是"成员表"（非语句块），逗号语义统一最不易错。
