【SKILL 不清楚 / 错误 / 缺失之处（引用原文 + 我的猜测）】
以下均为「SKILL 没写、我只能猜或绕开」的点，按影响排序：

1. **`range` 只有名字没有签名**。§6 写：「核心 / 数组（21）：`len` `range` `push` …」，但下方唯一的签名列表是「`push(v, xs)`、`pop(xs)`、`removeAt(i, xs)`…」——`range` 的签名从未给出（1 参？2 参？半开还是闭区间？）。
   → 我的处理：**完全不用 `range`**，所有下标循环用 `while` 手写。迷宫程序因此没有任何 `range` 调用。

2. **`let` 在循环体内重复执行的语义未定义**。§4-4 只演示顶层 `let a = 1` 后再赋值报 `TypeError`；§3/§7 没有任何「`let` 出现在 `while`/`for` 体内、每次迭代重新执行」的例子。若解释器把循环体视为同一作用域反复执行，`let c = …` 可能触发「不能重新赋值 let 变量」。
   → 我的处理：**循环体内的所有局部绑定一律用 `var`**（即使从不重赋值），顶层才用 `let`。

3. **`&&`/`||` 是否短路未写明**。§3 只给优先级表，没写求值策略。若 `&&` 不短路，`cy > 0 && !visited[c - W]` 在 `cy == 0` 时会先算 `visited[c-W]` 得负下标 → `IndexError`。
   → 我的处理：凡下标安全依赖短路的地方**改用嵌套 `if`**（`if cy > 0 { if !visited[c - W] { … } }`），不赌短路。

4. **`else if` 未出现在语法速查里**。§3 只演示 `if c { … } else { … }`。
   → 我的处理：写**嵌套的 `else { if … }`**（`isLinked` 里），不用 `else if` 组合。

5. **`if` 表达式的优先级不在 §3 的运算符优先级表里**（表只列二元运算符）。
   → 我的处理：作为 `+` 的右操作数时**加括号**：`row + (if c { "#" } else { " " })`。实测可行。

6. **函数读模块级 `let` 变量（闭包）未演示**。§7 例子里函数只用自己的参数/字段，没有「函数读取文件前面定义的全局变量」的例子；名字解析发生在定义时还是调用时未说明。
   → 我的处理：把 `isLinked` **定义在 `right`/`down` 之后**、调用更在其后，规避前向引用。

7. **`min`/`max` 是否支持两个标量参数未写明**。§6 明确它们是数组函数（`min(xs)`，空数组报错），没有 `min(a, b)` 形式。
   → 我的处理：两数取小用 `let lo = if a < b { a } else { b }` 手写，不用 `min`。

8. **内置函数是否是一等值（能否 `map(str, xs)`）未写明**。
   → 我的处理：路径字符串用 `while` + `str(route[i])` 拼接，不把 `str` 当函数值传。

9. **单行 `if c { stmt }` 未演示**（示例块全部多行）。
   → 我的处理：全部写成多行块，哪怕只有一句。
