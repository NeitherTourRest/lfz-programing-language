# B06 — 账户事件账本

## 统一执行与评分协议

1. 八题各用一个全新无历史 Agent，只提供本题任务书、冻结的 skill 四文件、解释器副本及本题独占目录。不得读源码、spec、旧程序、其他题答案或验收用例；不得联网。辅助 Agent 无团队启动/收工记录，禁止再委派。
2. 仅在项目 Temp/agent-benchmark-v2/<run-id>/<task-id>/ 内写入。交付 solution.lfz（首行 #42）及 REPORT.md。solve 为全局函数，不在顶层读 input、写演示文件或提前退出；可自定义辅助函数。
3. 每题最多 20 分钟、最多 5 次自行调用解释器进行调试。每次运行前先保存源码快照并记录命令/退出码/输出；修正程序不得覆盖首跑快照。到期即按当时产物验收；超时无产物记失败。
4. 交卷后由独立 verifier 对冻结的验收集运行。学生程序不得读取验收文件；运行器在项目 Temp 内合并函数与断言执行，单次解释器进程最多 10 秒；B08 每个用例用两个独立进程复验覆盖写，合计最多 20 秒。正式结果封存后不得原地修答案重算分数；修复另开一轮。
5. 主指标为交卷程序的整题通过率（该题所有功能用例通过且源代码约束核对通过），分母恒为 8。辅指标为首次自行执行成功率、用例通过数、调试次数、耗时及 skill/实现缺口。缺题、超时、禁止行为均算未通过，不从分母剔除。
6. 验收以行为为准，不设凑行数门槛。严禁硬编码本题示例或验收答案；不得通过调用其他语言/外部程序完成求解。性能约束仅考察给定有界输入及明显的重复扫描；不声称本基准代表所有工程任务。
7. 运行器自测不等于 Agent 盲测；运行器的 PASS 不可记作八题完成。实际盲测开始前记录 run-id、Agent/model 信息、提示词和 skill/解释器 hash。模型可见了验收或参考解，则该轮不具备隔离资格，记录为协议失败。



交付 fn solve(events)，返回 {balances:struct,rejected:int}。事件 ["deposit",id,amount] 入金；["transfer",from,to,amount] 转账。amount 为正 int，账户 id 为任意字符串，每个 id 最多 128 个 Unicode 标量。所有被提及账户（包括被拒绝转账的双方）均出现在 balances 中，初值0。转账前余额不足则本次拒绝、rejected+1，两边余额不变；足额则原子扣/加；同账户转账足额时余额不变，不足时仍拒绝。最多128事件，金额及累计额不溢出。每次 solve 从空账本开始。验收覆盖未知账户、拒绝不部分扣款、自转账、Unicode id、守恒及多次调用独立性。
