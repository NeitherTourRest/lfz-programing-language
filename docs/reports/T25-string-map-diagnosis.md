# T25 string_map 分段诊断

固定 8,000 元素、每进程重复 12 次。T12 与当前候选交替写入同一项目内执行路径，各块等待 2 秒后执行五个用例。每轮轮转用例顺序，先进行一轮预热，然后六轮正式采样。70 次启动均核对输入、执行文件、退出码、stdout 和空 stderr。原样本见 [phase-window.json](../../benchmarks/t25/results/phase-window.json)。

| 用例 | T12 中位数 | 当前中位数 | 当前 / T12 |
| --- | ---: | ---: | ---: |
| 空循环 | 8.746 ms | 9.681 ms | 1.107 |
| 完整链路 | 91.725 ms | 97.167 ms | 1.059 |
| 两轮映射，含插值和 trim | 82.921 ms | 87.461 ms | 1.055 |
| 预先准备输入后的 join / replace / split | 22.699 ms | 22.065 ms | 0.972 |
| 单轮恒等映射 | 25.139 ms | 28.015 ms | 1.114 |

结果将优化候选缩小到回调调用路径。恒等映射保留回调和输入快照，移除了字符串插值、trim 和后处理，仍有可见差距。分段程序的准备、循环和校验不同，中位数不能直接相减后当作各实现步骤的耗时。空循环存在约 0.94 ms 差距，短进程启动仍是影响因素。当前证据无法在数组快照、实参 Vec、调用作用域和每节点执行限额检查之间做因果归因。
