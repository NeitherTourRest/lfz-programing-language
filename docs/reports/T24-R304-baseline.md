# T24 当前候选 R304 诊断

2026-11-16 对已交付候选 `76ac4cb…f11e` 执行一次完整窗口。原协议的 532 次正式样本和 152 次预热全部满足原有输出预期。19 项判定为 **11 通过、6 环境不确定、2 失败**，R304 保持开放。两个基线和新候选均逐次校验，递归源码及 Cargo 指纹在窗口前后一致。原样本、复算与测量回执见 [T24 结果](../../benchmarks/t24/results/)。

`struct_ops 8000` 仍达到原 30% 降时目标。六个环境不确定用例是 noop、array_builtins 1000/10000、string_ops 2000、struct_small 4/16。它们在当前与同期旧版上同时越过各自原门槛。九项 JSON/CLI 能力组均通过输出预期。T12 到当前候选的能力组中位数比值约 0.950–1.130。该窗口未测峰值内存。

`string_map 8000` 当前候选七次正式样本全部越线，最小也为 26.404 ms。脚本执行两轮映射，共调用回调 16,000 次，然后连接、替换和拆分字符串。源码上 `h_map` 创建输入快照，`call_value` 为回调克隆实参到 Vec，`call_user` 建立新作用域并维护诊断。T13 已尝试移除其中的中间分配，但当时未获得足够性能证据而撤回。下一步先拆开测回调与字符串整段开销，再选要改的路径。需保留回调期间对原数组的修改语义及真实跨模块调用栈。

`struct_small 64` 当前候选七次样本中四次越线，两侧分布重叠。脚本反复创建结构、按动态字符串键插入和读取，并通过 `keys` 取按 UTF-8 字节序排序的数据键。可分别测值插入、重复查找、插值造键和排序开销，确保比较的是相同数据规模与可观察键序。现有总时包括启动、解析、数据准备和求值，CPU 时间量化较粗，这些观察提供排查方向，尚不足以定位回归。

本轮唯一正式窗口和历史失败保留。后续诊断实验需单独标注，原门槛继续使用。此轮交付测量和定位记录，解释器沿用已验收的二进制。
