# T26 B 原 R304 独立审计

候选 B 在这一正式窗口通过原 R304 测量条件。19 个旧负载全部在原绝对固定线内，无失败或环境不确定。`struct_ops 8000` 中位数 17.5651 ms，相对原 89.4598 ms 减少 80.3654%，低于原 30% 降时目标的 62.62186 ms 上限。候选 `Temp/T26-perf/prototype-b.exe` 为 1119232 字节，SHA256 `7a14421320bc93d460d3be9abf48aa89b9c8091f7c6fc928ee11e860e52aa8ef`。原始窗口 SHA256 `de2b47b7c6bf4e6c75432e250058df723b821d0fd0c832db6df3f6a263ac5f4a`。

独立核对 T13 固定协议及支持脚本原字节，从原两份 T12 baseline JSON 重建 19 例和阈值。noop 阈值为 `max(原中位数 × 1.30, 原中位数 + 5 ms)`，其余为 `max(原中位数 × 1.20, 原中位数 + 5 ms)`。两个冻结基线和候选实物 SHA 均与记录匹配，回执 27 项递归源码和 Cargo 哈希与当前工作区一致。核对 76 组、684 条记录，含 152 次预热和 532 次正式样本。19 个旧负载的 old/t12/new 顺序轮换，9 个能力用例的 t12/new 交替。逐条核对执行身份、连续组内序号、阶段、退出 0、精确 stdout 和空 stderr。57 个主组、18 个能力组及 1 个候选路径探针的正式中位数、区间和 CPU 中位数均独立重算一致。

九项 JSON/CLI 能力输出全部满足独立 oracle。JSON 2k/4k/8k 的紧凑 UTF-8 输入由 Python 独立生成并核对字节数和 SHA，每进程 20 次操作。按原冻结规则扣同窗 noop 13.2434 ms，parse 总中位为 21.1410/33.8022/59.5695 ms。2k 启动占比 62.64%，仅报告总时，4k→8k 可比较的近似净耗时比为 2.25335，低于 3.0。stringify 总中位 12.4550/15.6057/21.2690 ms，所有档位启动估计占比至少 50%，按规则仅报告总时。2k 总时小于单独 noop 中位数，说明跨组相减不适合作为该负载的吞吐估计。CLI `-e`、stdin、argv 的 B 总中位分别为 8.9053/9.7918/9.4894 ms。

独立探针在候选的实际测量路径得到 numeric_loop 500000 中位数 87.6354 ms，保留在正式 19 项之外。该路径是临时候选文件，交付文件可通过相同 SHA 校验身份。通过结论限定为本机、本窗口、未改亲和性、固定协议的整体进程耗时。启动、解析、I/O、执行均计入，未测峰值 RSS。表内候选同时存在慢于同期旧版或 T12 的项目，原绝对线通过并不等于普遍加速。审计核对的是冻结驱动与完整记录，未在测量现场观察系统调度。

只读重算已对 `benchmarks/t26/results/gate-b.json` 和回执实际复验。复现脚本为 `T26-independent-evidence/audit.py`，从项目根目录运行，需保留项目 Temp 内两冻结基线、B 候选、生成输入和 `Temp/T26-verifier`。本轮审计执行 Python 共计零 LFZ 性能进程，未构建或修改产品。
