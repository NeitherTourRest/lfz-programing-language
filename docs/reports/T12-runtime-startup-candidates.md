# T12 启动与短任务构建候选

> 2026-10-25 23:16，runtime-dev。仅隔离候选数据；主Cargo/profile与dist均未改。本报告不宣布原性能门槛全部通过。

## 结论

建议将 **opt-level=2** 作为明确的体积/启动取舍候选交team-lead决定：在当前已完成while优化的同源代码上，体积从821760B降至759808B（约7.54%），noop中位17.9451→14.6609ms；500k循环88.4131→89.6030ms，大对象8k为23.3245→21.1936ms，保留主要收益。其余选定负载有约2%–7%的相对成本增加，应作为取舍公开说明。

opt-level='s'可降至632320B，但500k为108.1174ms，相对7641约慢22.3%，不是本轮优先建议。两候选都没有令本机当前条件下所有原门槛通过；不能用体积变小或单个noop通过代替完整性能验收。

## 固定方法

- 测量前先记录method.json，选定8case与版本顺序，不看结果后改规模或阈值。两候选仅在隔离Cargo里增opt-level=2/s，其余lto=true、codegen-units=1、strip=true保持。源文件逐字来自当前优化后的实现。
- 旧149b、当前7641、opt2、opts共4版，统一subject.exe路径，换字节后核SHA并固定等5秒；每variant/case2次预热+7正式，case间版本块顺序正反交替。默认无绑核，不改系统设置。
- 整体进程计时含启动、加载、求值和输出捕获；cwd项目根，TEMP/TMP项目内。288次进程输出和退出码全部核对正确。后台系统负载未完全控制。
