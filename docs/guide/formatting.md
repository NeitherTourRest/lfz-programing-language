# 用 fmt 整理 LFZ 文件的空白

在项目目录执行 `lfz fmt main.lfz`。命令读取一个文件，检查其语法，并将格式化后的 UTF-8 字节写到 stdout。成功退出码为 0。读取或检查失败时退出码为 2，诊断写到 stderr，stdout 为空。若 stdout 写入本身失败，输出可能只有前半段，同样退出 2。

`fmt` 不执行文件，也不加载 import 依赖。格式化只接受一个路径，路径含空格时用引号，文件名以连字符开头时可用 `lfz fmt ./-draft.lfz`。已有的裸文件调用 `lfz fmt` 仍按脚本名 `fmt` 处理，`lfz run fmt` 也仍可运行该脚本。

## 保存到另一个文件

Windows 下在命令提示符（cmd.exe）中执行以下两行，以原样保存 stdout 字节。这条命令要求 `lfz.exe` 已在 PATH 上，并以一个新的输出路径为例。

```cmd
lfz.exe fmt "source file.lfz" > "formatted file.lfz"
echo %ERRORLEVEL%
```

确认退出码为 0，再检查新文件。`>` 会在 LFZ 启动前打开并截断目标文件，即使格式化失败也可能留下空文件。输出路径须与输入文件不同，也应避免覆盖已有文件。部分 PowerShell 版本的 `>` 会按文本处理原生命令输出，可能改变编码或换行。需要字节保真时，用上面的 cmd 命令。

## 哪些空白会变

- 每个物理行开头的代码空白中，一个 ASCII Tab 换成一个 ASCII 空格。LFZ 将两者各计为一列，所以后续 token 的列号保持不变。
- 每个物理行末尾及 EOF 前的代码空格和 Tab 会被删除。纯代码空白行也适用。如果删除会让前一行的裸 CR 和本行的 LF 合并为 CRLF，该段空白会保留。
- 文件的 BOM、已识别的 `#42` 前导、原有 LF/CRLF/裸 CR 和末行终止状态原样保留。注释中的空白、字符串与插值、token 之间的空白、数字拼写等也原样保留。

例如，行首为 Tab 的 `print("你好")`，若右括号后有两个空格，格式化后行首为一个空格，右括号后的两个空格被删除。字符串中的空格和行注释末尾的空格属于原文本。

格式化保留 LFZ 执行时可观察的错误行列和调用帧位置。诊断显示的源码行会反映新的空白，终端绘制 Tab 时的视觉宽度也可能不同。显式读取源码文件字节的程序仍能读出这些空白变化。精确规则见 [接口契约 §27](../spec/interface-contract.md#27-t21-保真空白格式化2026-11-13-冻结)。
