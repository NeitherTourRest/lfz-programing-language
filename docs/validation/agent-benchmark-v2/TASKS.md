# LFZ Agent 编程基准 v2 — 固定八题任务书

> 制定：team-lead，2026-10-24。用户明确要求重写题目，取消寻找旧题的前置条件。
> 这是新基线 LFZ-AGENT-BENCH-v2，不是历史同题重跑；旧 2/8 只作历史记录，不计算提升百分比。
> 本文件、验收用例、运行器及输入解释器/skill 的 SHA256 必须在正式测评前冻结。改题或改验收条件必须升版，不能在看到答案后降低标准。

## 统一执行与评分协议

1. 八题各用一个全新无历史 Agent，只提供本题任务书、冻结的 skill 四文件、解释器副本及本题独占目录。不得读源码、spec、旧程序、其他题答案或验收用例；不得联网。辅助 Agent 无团队启动/收工记录，禁止再委派。
2. 仅在项目 Temp/agent-benchmark-v2/<run-id>/<task-id>/ 内写入。交付 solution.lfz（首行 #42）及 REPORT.md。solve 为全局函数，不在顶层读 input、写演示文件或提前退出；可自定义辅助函数。
3. 每题最多 20 分钟、最多 5 次自行调用解释器进行调试。每次运行前先保存源码快照并记录命令/退出码/输出；修正程序不得覆盖首跑快照。到期即按当时产物验收；超时无产物记失败。
4. 交卷后由独立 verifier 对冻结的验收集运行。学生程序不得读取验收文件；运行器在项目 Temp 内合并函数与断言执行，单次解释器进程最多 10 秒；B08 每个用例用两个独立进程复验覆盖写，合计最多 20 秒。正式结果封存后不得原地修答案重算分数；修复另开一轮。
5. 主指标为交卷程序的整题通过率（该题所有功能用例通过且源代码约束核对通过），分母恒为 8。辅指标为首次自行执行成功率、用例通过数、调试次数、耗时及 skill/实现缺口。缺题、超时、禁止行为均算未通过，不从分母剔除。
6. 验收以行为为准，不设凑行数门槛。严禁硬编码本题示例或验收答案；不得通过调用其他语言/外部程序完成求解。性能约束仅考察给定有界输入及明显的重复扫描；不声称本基准代表所有工程任务。
7. 运行器自测不等于 Agent 盲测；运行器的 PASS 不可记作八题完成。实际盲测开始前记录 run-id、Agent/model 信息、提示词和 skill/解释器 hash。模型可见了验收或参考解，则该轮不具备隔离资格，记录为协议失败。

## B01 — 整数表达式解释器

交付 fn solve(source)，返回 int。输入为有效表达式；支持非负十进制整数字面量、ASCII 空格、二元 + - * /、括号、任意多个一元 + / -。二元运算左结合，乘除优先于加减，一元优先于乘除；/ 使用向负无穷取整的整数除法。无除零，所有中间结果均在 i64 范围内；表达式长不超过 256 字符、嵌套不超过 16 层。不要求处理无效表达式。示例 solve("2 * (3 + 4) - 5") == 9，solve("-7 / 2") == -4。要求自行解析，不用固定文本替换拼答案。验收覆盖优先级、结合性、空格、连续一元与嵌套。

## B02 — CSV 解析器

交付 fn solve(source)，返回 array[array[string]]。有效 CSV：逗号分列，LF 或 CRLF 分行；字段可双引号包裹，包裹字段内允许逗号、换行，双双引号表示一个双引号。非包裹字段不含双引号/行终止符；包裹字段结束后紧跟分隔符或文本末尾，不含额外空格。保留字段空格、空字段与 Unicode；包裹字段内 CRLF 原样保留。空输入返回 []；一个行终止符表示一行单个空字段；末尾行终止符不额外生成空行。末尾逗号产生空字段。输入不超过 2048 字符。例 a,b\n → [["a","b"]]（此处 \n 表示真实 LF）；a, → [["a",""]]。验收覆盖转义引号、空/尾字段、中文 emoji、包裹字段内换行。

## B03 — 碰撞桶字符串哈希表

交付 fn solve(operations)，返回每次操作结果组成的 array。操作为 ["set",key,int] → nil（插入或覆盖），["get",key] → 对应 int 或 nil，["has",key] → bool，["delete",key] → 原来存在则 true 否则 false，["size"] → int。key 为任意字符串（含空串与 Unicode），每个 key 最多 128 个 Unicode 标量，最多 128 次操作，最多 32 个不同键。

必须自己实现固定 8 桶的链式碰撞表：hash = 所有 Unicode 标量码点之和 mod 8；每桶存储键值对数组并用完整 key 区分碰撞。禁止用 struct 的动态字符串字段直接替代哈希表。内部结构/哈希算法由 verifier 查源码核对；行为验收覆盖同桶键、覆盖不增 size、删除后重插、空键与 Unicode。solve 每次调用独立初始化。

## B04 — 网格最短路径 BFS

交付 fn solve(grid,start,goal)，返回从 start 到 goal 的坐标路径 array[[row,col]]，包含首尾，无路返回 []。grid 为矩形 array[string]，仅 .（通路）与 #（墙）；行数与列数均为 1..20。坐标 0 起始，输入首尾总在界内且为通路。必须用 BFS，扩展邻居次序固定为上、右、下、左；节点第一次入队即标记访问，不重复覆盖前驱。多条最短路按该次序决定唯一结果；起终点相同返回 [start]。不得修改 grid/start/goal。验收覆盖障碍绕行、无路、单点与多解次序，检查源代码确为 BFS。

## B05 — 0/1 背包及回溯

交付 fn solve(items,capacity)，返回 {value:int, indices:array[int]}。items 为 [[weight,value],...]，weight 为正 int，value 为非负 int；每项至多一次，capacity 为非负 int。最多 24 项，capacity≤80，所有物品价值之和不超过 i64::MAX。indices 升序、0 起始，返回最优总价值及选择项。用按原下标顺序加入物品的二维 DP：候选价值与不选本物品价值相等时必须不选本物品；从最后一项回溯形成唯一结果。空输入/容量0 返回 {value:0,indices:[]}。验收覆盖容量边界、相同价值取舍、重复物品、全放不下、回溯结果与总重/价值一致。

## B06 — 账户事件账本

交付 fn solve(events)，返回 {balances:struct,rejected:int}。事件 ["deposit",id,amount] 入金；["transfer",from,to,amount] 转账。amount 为正 int，账户 id 为任意字符串，每个 id 最多 128 个 Unicode 标量。所有被提及账户（包括被拒绝转账的双方）均出现在 balances 中，初值0。转账前余额不足则本次拒绝、rejected+1，两边余额不变；足额则原子扣/加；同账户转账足额时余额不变，不足时仍拒绝。最多128事件，金额及累计额不溢出。每次 solve 从空账本开始。验收覆盖未知账户、拒绝不部分扣款、自转账、Unicode id、守恒及多次调用独立性。

## B07 — 文本倒排索引

交付 fn solve(text,queries)，返回每个 query 的 [normalizedQuery,count,positions] 组成的 array。词定义为连续 ASCII 字母 A-Z/a-z；统一为 ASCII 小写，非 ASCII 字符和数字/标点均分隔单词。positions 是该词在全文 token 序列中的 0 起始下标，升序；不存在则 count0/positions[]。queries 每项为 1..64 字母的纯 ASCII 字母串，仅作大小写归一，不拆分。text≤4096标量，queries≤32。例 text="Cat, dog CAT!"、queries=["CAT","bird"] → [["cat",2,[0,2]],["bird",0,[]]]。先构建索引再查，不为每条 query 重扫全文；源码核对该约束。验收覆盖标点、空文本、大小写、重复 query、Unicode 分隔与词位置。

## B08 — 文件流水账转换

交付 fn solve(inputPath,outputPath)，返回 {count:int,total:int}。输入为 UTF-8 文本，LF/CRLF 分行，各非空行（trim 后）是有效有符号十进制 int；忽略空白行；无 BOM，不会出现整数溢出；最多128行。输出 UTF-8、无 BOM、固定 LF：首行 index,value,running\n，其后每条有效输入按 1 起始序号写 index,value,累计和\n。输出文件必须覆盖旧内容，输入文件不得修改；输入输出路径互不相同，父目录已存在，路径可能含中文或空格。count 为有效行数；空输入也写完整表头，total0。示例输入 3\n-1\n → 输出 index,value,running\n1,3,3\n2,-1,2\n，返回 {count:2,total:2}。必须真实调用 LFZ 文件 IO 内置；外部验收逐字节比较输出、重复运行覆写、输入保持与返回结果。错误路径的语言行为已有黑盒覆盖，本题只提供可读输入与可写输出。
